# 图片库统一嵌入

`/gallery/` 是唯一图片库页面，保留独立入口。工作台 `/text2image/gallery` 保留顶部栏和左侧导航，右侧通过同源 iframe 直接加载 `/gallery/`。工作台不再维护图片库搜索、上传、卡片或操作逻辑。

`frontend/src/pages/GalleryPage.jsx` 只负责页面加载、iframe 尺寸、剪贴板权限和返回工作台的导航。`GalleryPage.css` 只设置容器样式。图片库自身的 UI、响应式布局和功能均由 `/gallery/` 的发布产物提供；发布图片库后，两处入口都使用新版本。

iframe 允许 `clipboard-write`，使用同源会话 cookie。独立页面内指向工作台的链接在顶层打开，避免嵌入另一层工作台。切换离开图片库会卸载 iframe，重新进入时加载当前图片库页面。

## 路由

生产 Nginx 中删除 `/text2image/gallery` 和 `/text2image/gallery/` 跳转 `/gallery/` 的规则，由现有 `/text2image/` SPA 回退处理路由。保留 `/gallery/` 的独立静态目录。

## 本地开发

同时运行工作台和独立图片库：

```powershell
npm --prefix standalone-gallery run dev
npm --prefix frontend run dev
```

工作台 Vite 将 `/gallery` 代理到独立图片库的 5174 端口，保持 iframe 与外壳同源。后端接口继续使用已有 `/text2image/api` 代理。

## 验收

确认嵌套路由保持 `/text2image/gallery`，右侧 iframe 地址为 `/gallery/`；浏览器窗口改变时图片库随 iframe 宽度自适应；复制图片写入 PNG；“生成图片”跳转顶层工作台；独立 `/gallery/` 继续可直接访问。
